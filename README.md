# TimeCraft Local

TimeCraft Local 是一個免帳號、免後端、免 Notion 的個人工時與專案工作台。

所有工時、專案與偏好設定都只保存在目前瀏覽器的 `localStorage`，適合個人學習、開發紀錄與離線使用。

**線上試用：** <https://person-work-notion-plan.vercel.app>

## 為什麼做這個

工作上做過的事，做完就忘了。等到要寫週報、回顧一季、或被問「這個專案花了多少時間」的時候，才發現手上什麼紀錄都沒有。

TimeCraft 一開始是我自己的工具：用半小時一格的週表把時間記下來，再用甘特圖看每個專案累積到哪裡。它幫我回答兩個問題——**我最近到底在忙什麼？每件事進度在哪裡？**

這個公開版拿掉了我個人使用的登入與 Notion 同步，只保留打開就能用的核心功能。

## 功能

- 週網格工時排程
- 專案甘特圖
- 工作／個人範圍分類與分開統計
- 專案與常態維運管理
- 多國行事曆（台灣、日本、新加坡、美國）
- 0.5 小時工時顆粒度
- 不需註冊、登入或提供外部服務金鑰

## 我怎麼用它

> 以下是我自己的習慣，提供參考，不是唯一用法。

- **每天下班前花 5 分鐘補時段。** 當天記最準，隔天就只記得大概。
- **工作和個人分開。** 上班的專案放「工作」，下班的自學和個人作品放「個人」，兩邊的時數分開看，才知道自己的時間真正花在哪。
- **專案和維運分開。** 有起訖的開發放「一般專案」，Graylog、Zabbix 這類沒有終點的例行維護放「常態維運」，甘特圖才不會被維運拉得很長。
- **週五看甘特圖寫週報。** 每個專案的時數和進度都在上面，週報幾乎是照抄。
- **每月備份一次。** 資料只在瀏覽器裡，方法見下方「資料與隱私」。

## 本機啟動

需求：Node.js 20 以上。

```bash
npm install
npm run dev
```

開啟 <http://localhost:3000>。不需要建立 `.env.local`；若要覆寫時區，可參考 `.env.example`。

## 部署自己的一份

這是一般的 Next.js 專案，可以部署到 Vercel 或任何支援 Node.js 的平台：

1. Fork 這個 repo。
2. 在 Vercel 匯入你 fork 的 repo，不需要設定任何環境變數，直接部署。

注意：每個網域的 `localStorage` 各自獨立。換成自己的網址後，原本在其他網址上的紀錄不會自動搬過去，請先備份再還原。

## 延伸玩法：把它變成自己的人生 PM

公開版刻意保持「只用瀏覽器」。如果你想要跨裝置同步、長期保存，或和其他工具串在一起，下面是我實際走過或正在考慮的方向。**這些都不是內建功能**，需要自己動手改。

| 方向 | 適合 | 做法提示 |
| --- | --- | --- |
| 接 Notion | 已經用 Notion 管理任務、想在同一個地方看工時 | 透過 Notion API 把工時寫進一個 database；金鑰只放在伺服器端環境變數 |
| 接 SQLite | 想要一個自己掌握、可以查詢分析的資料庫 | 在伺服器端用 SQLite（或 Turso 等託管版本）存工時與專案 |
| 私人雲端部署 | 想在手機、公司電腦、家裡電腦都看到同一份紀錄 | 部署到自己的 Vercel 專案，並加上登入保護 |

改造時可以從這兩個檔案下手：

- `lib/storage.ts`：`loadWorklogs`／`saveWorklogs`、`loadProjects`／`saveProjects` 是讀寫資料的出入口，把 `localStorage` 換成 API 呼叫即可。
- `lib/sync.ts`：已經有合併本機與遠端紀錄的函式（例如 `mergeWorklogs`），可以拿來處理同步衝突。

一旦接上外部服務，資料就不再只在你的瀏覽器裡：

- API 金鑰、資料庫連線字串只放在環境變數，**不要 commit 進 repo**。
- 部署到公開網址時一定要加登入保護，否則任何知道網址的人都能看到你的紀錄。
- 公開分享 fork 之前，確認沒有把私人設定或真實工時留在程式碼裡。

## 資料與隱私

- 資料不會上傳至 TimeCraft、Notion 或其他資料庫。
- 不同瀏覽器、裝置與網域的資料彼此獨立。
- 清除網站資料、無痕模式結束或瀏覽器重設可能移除所有紀錄。
- 請勿將 localStorage 視為加密或雲端備份。
- 備份與還原步驟見 [Public SOP](docs/PUBLIC_SOP.md)。
